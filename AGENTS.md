# AGENTS.md

Kiki: AI running coach iOS app. Quiz onboarding → AI-generated training plan → paywall → daily coaching. Black/white brand, premium minimal UI.

## Brand
- Look: black/white UI, premium and minimal. Photography and video bring warmth (golden-hour running footage), never the UI chrome.
- Texture: gritty, asphalt-like film grain with a soft vignette (darker edges, gentle center glow). Used on the splash (`LaunchTexture`) and over the welcome video (`Grain`). Keep it subtle.
- Welcome screen: the Kiki wordmark centered at the top (24pt black italic, over a soft vignette); centered at the bottom over a dark gradient: the headline (44pt black italic, tracking -1.2), Get started, and an "Already have an account? Sign in" text link.
- Website: dark by default (`--paper` #0B0C0E, `--ink` white), `.asphalt` texture on hero/feature bands, Inter (true black italic) for headlines. No pricing on the website.
- Website pages (`nextjs/app/(site)`): Home (hero with the welcome film + Home screenshot, goals, six feature rows with real screenshots in `PhoneShot`, how it works, principles, guides, FAQ, final CTA), `/guides` + `/guides/[slug]` (articles in `lib/guides.ts`: a short direct answer first, then sections, tables, FAQ; Article/Breadcrumb/FAQ JSON-LD), support/privacy/terms. Primary CTA everywhere is Apple's official "Download on the App Store" badge (`public/app-store-badge.svg`, unmodified) via `AppStoreBadge`/`DownloadCTA`, linking to `site.appStoreUrl` (`apps.apple.com/app/id6817469393` unless `NEXT_PUBLIC_APP_STORE_URL` is set). iPhone only: never mention Android or "coming soon". SEO: `app/sitemap.ts`, `app/robots.ts` (AI crawlers allowed, `/api/` disallowed), `app/llms.txt/route.ts`, static `app/opengraph-image.png`, Smart App Banner (`itunes` metadata), MobileApplication/Organization/FAQPage JSON-LD on Home.
- Marketing screenshots (`public/screens/*.png`, 603px wide) come from the Debug app signed in as the demo runner "Sam" (`test+kiki@kikirunning.com`, user `0BKyGxY6oZ66p6Wb7RbYE3koy9ZR14nu`; launch with `KIKI_DEBUG_SESSION_TOKEN`/`KIKI_DEBUG_USER_ID`): a Chicago Marathon plan (race Sun Oct 11, 2026, goal 4:00:00, started Jul 20) with ten weeks of logged runs, captured on Oct 2 with the status bar overridden to 9:41. Never use a real person's name or data in marketing.
- Voice: ask and speak like a coach would. Natural, concise, direct and simple: "Which race are you training for?", not "What distance is your race?". Short subtitles, no filler, no jargon. Keep it warm and positive (e.g. "Sign in", "Welcome back!").

### Design system (iOS, `ios/kiki/Design/`)
Every screen is built from these files. Never use raw numbers, hex colors, fixed font sizes or one-off card styles in feature code: if something is missing, add a token or component here first, then use it. Changing a value here restyles the whole app. `DesignCatalog.swift` previews every component (light and dark).
- `Tokens.swift`: `Spacing` (4pt scale: xxs 2 … xxxl 32), `Metrics` (20pt screen margin, 8pt top inset, 58pt large-title inset matching Apple's large titles (every tab), 18pt below a pushed screen's nav bar (matches Settings > General), 28pt section spacing, 12pt section header spacing, 20pt card padding, 56/48pt buttons, 44pt tap target), `Radius` (card 24, bubble 20, control 16, inner 12), `Elevation` (`.card`, `.raised`), color roles (`hairline`, `track`, `destructive`), `Haptics`.
- Colors (Assets, light + dark): `ink` text/controls, `paper` text on ink, `canvas` page, `surface` cards and controls, `wash` small fills on cards (icon circles), `muted` secondary text (5.5:1, never `.secondary`). Grayscale plus one accent, Volt: `Color.highlight` (`#CEFF00` in `Tokens.swift`; swap it there to try another accent), with `Color.onHighlight` (near-black) for anything on it. Use it sparingly; too much is overwhelming.
  - Use Volt for: progress on the goal card only, a Volt fill on `Color.highlightTrack` (#2A2C30, a softened near-black: Volt needs a dark track to be seen) via `ProgressBar(isHighlighted: true)`; every other bar and ring (`ProgressBar`, `ProgressRing`: This week, the Plan tab ring) is a black fill on the light `track`; a bar always measures the same thing as the label beside it; completed runs, a Volt circle with a black check (This week strip, Plan schedule, fully completed weeks); a faint Volt glow on the dark goal card (`AsphaltBackground`, top-right, subtle enough to read as light); celebration confetti.
  - Never use Volt for: buttons or their icons (Start run, Save and every other button stay black with white content); selected states (black); text, links or thin lines on white (Volt is too light to read there). Keep text at WCAG AA.
- `Typography.swift`: `display`/`wordmark` (black italic, the Kiki voice), `screenTitle` (34 bold), `heroTitle` (22 bold, the goal card's title), `cardTitle`/`sheetTitle`, `sectionTitle` (20 semibold), `rowTitle` (17 semibold), `body`, `detail` (15, with `muted`), `eyebrow` (13 semibold, with `muted`), `metric(_:)`, `.heroMetricFont()`. All follow Dynamic Type. Use weight, not ALL CAPS, for emphasis.
- `Surfaces.swift`: one surface model. Every page sits on `PageBackground()` (canvas with a faint asphalt glow from the bottom). Content goes on `Card { }` / `.elevatedCard()` (white surface, soft shadow). Controls (options, fields, tiles) use `.controlSurface(isSelected:)` (white + hairline, ink outline when selected). Only Home's goal card is dark (`AsphaltBackground`); everything else (Today's workout, the Plan tab's stats card) stays white. If a dark card is ever needed, use `.invertedColorScheme()`, never `inverted` flags.
- `Pages.swift`: every screen is a `TabPage` (tab roots: `TabPage("Title")`, a 34pt left-aligned title that scrolls away, no nav bar; Home's title is a time-of-day greeting on two lines ("Good evening," / "Stuart!") at the same height as other tabs' titles; no wordmark or date (`TabPage(_:eyebrow:showsWordmark:)` still exists, unused) ("Hello!" without a name; `TabPage(.wordmark)` exists but is unused), then the goal card: the goal as its title (`Plan.displayName`: the race name, else the goal, 22pt bold) with a faint `figure.run` watermark top right, the race date (plus "Goal 3:45:00" for time goals) in gray, then the countdown and progress), a `DetailPage` (pushed screens and full sheets: inline nav title, page background; the tab bar hides while pushed: put `.hidesTabBar(!path.isEmpty)` on each tab root, never hide it from the pushed screen, which makes it pop back in late), or a `FlowPage` (full-screen flow steps: `PageHeader` + content + actions; onboarding uses it via `OnboardingScaffold`). ## Backend
- pnpm. `pnpm dev`, `pnpm build`, `pnpm lint`, `npx tsc --noEmit` (run `npx next typegen` first if route types are stale).
- DB: Neon Postgres (project "Kiki", `summer-wave-37335605`) via Drizzle. `db/schema.ts` is the only schema source. Don't modify `db/index.ts` or `drizzle.config.ts`. Schema auto-pushes on merge via `.github/workflows/push-db-schema.yml`; locally: `pnpm exec drizzle-kit push`. neon-http driver: no interactive transactions, use `db.batch`.
- Units: distances in meters, durations in seconds, paces in s/km, calendar dates as `YYYY-MM-DD` strings.
- Auth: Better Auth (`lib/auth.ts`), **Sign in with Apple only** (native ID token, audience = bundle ID), `bearer` plugin. iOS sends `Authorization: Bearer <token>`. `withUser()` in `lib/api.ts` wraps every API route.
- Apple token revocation (5.1.1(v)): after sign-in the app posts the authorization code to `/api/me/apple-token`; `lib/apple.ts` exchanges it for a refresh token (stored in `account.refreshToken`) and `DELETE /api/me` revokes it. SIWA key ID `NZ56QW5STV`.
- AI: AI SDK + AI Gateway, model `google/gemini-3.8-flash` (thinking level low: a plan takes ~15s) with `anthropic/claude-sonnet-5.5` fallback, structured output (`Output.object` + Zod). A plan is ONE AI call. The prompt (`COACH_SYSTEM` in `lib/training/coach.ts`) is a world-class coach tailoring the plan to the runner; keep it broad (safety first, push when asked or experienced, realistic plans for ambitious timelines), not prescriptive rules. The AI only uses four workout types (`PLAN_WORKOUT_TYPES`: easy, long, tempo, intervals; other days are rest; new and beginner runners get only easy (run/walk steps where needed) and long), labels each week's phase (base/build/peak/taper, stored on `workout.phase`, not shown yet), and gives one target pace per effort (`paces`, s/km; no ranges). Titles and one-line descriptions are fixed copy (`WORKOUT_COPY`), so every workout of a type reads the same. Adjustments are targeted edits, scoped to a day (`targetDate`) or the whole plan: the AI sees the last three weeks of workouts and runs (effort, feeling, notes) and returns only the days that change, so it's fast (~2–8s). Code safety nets: run days only, a loose guard against runaway weekly jumps, the goal finale.
- Goals: `goalKind` is `start` (run 30 min non-stop), `race`, `faster` (time trial finale) or `fit` (no finale). `plan.raceDate` is the plan's end date for every goal. Phases are data only (not in the UI yet); keep wording beginner-friendly and jargon-free.
- Workflows (Vercel Workflow): `generatePlanWorkflow` (load context, one AI step, save) and `adjustPlanWorkflow`. The AI work runs inside `"use step"` functions. `app/.well-known/workflow/` is generated (gitignored).
- Consent: new accounts tick "I agree to Kiki's Terms of Service and Privacy Policy" (clickwrap) on the onboarding account step; the welcome "Sign in" opens a styled bottom sheet (`SignInSheet`: "Sign in with Apple" plus a "By continuing, you agree…" notice, no checkbox), and `ConsentGate` asks once if the server has no agreement on record. Agreements are logged in the append-only `consent` table (`POST /api/me/consent`) with the legal pages' "last updated" date (`Config.legalVersion`) for the record. No re-consent on Terms changes (the Terms cover updates).
- Subscriptions (paywall ON: `PAYWALL_ENABLED` on the server, `Config.paywallEnabled` in the app): the paywall is RevenueCat's dashboard paywall ("Kiki Paywall 1" on the current `default` offering), loaded with RevenueCatUI's `PaywallView()` in `KikiPaywall` (`Features/Paywall`), presented full screen from `RootView` via `Subscriptions.presentPaywall(source)`: no swipe to dismiss; its own "Continue with limited access" closes it (`onRequestedDismissal`), as do a purchase or restore. Never build a custom paywall or call `purchase()` beside it. Shown right after onboarding, and on launch once the free week is over. Limited access (`Core/Store/Access.swift`): the app works (track, log, mark done), but plan days after `Plan.freeThrough` (end of the plan's first week, or second if it starts Thu–Sun) are locked: the Plan list shows a blurred next week under `LockedCard`, the calendar dims them (tap → paywall), Home's Today/Tomorrow and Next week show `LockedCard`. Pro-only actions use `ProOnly` (a small lock sheet → paywall): adjust day/plan, share plan, plan updates from Profile edits or a hard run; changing the goal opens the paywall. Profile: "Upgrade to Kiki Pro" (free) or Subscription → Customer Center (Pro), plus Restore purchases. Server: adjustments require the `premium` entitlement (RevenueCat v1 API); plan creation allows 3 free.

## iOS
- Run tracker (`Features/Tracker`): a sheet (swipe down anytime). Swiped away before Start it closes; during a run it keeps recording and `ActiveRunPill` (black, Volt dot pulsing, "Running"/"Paused", time and distance) floats above the tab bar on the right: tap to return. During a run the middle button shows pause (play when paused): it pauses/resumes and reopens the tracker, never restarts. GPS warms up when the tracker opens ("Finding GPS… / GPS ready"); progress is saved every few seconds to Application Support so a closed or crashed app resumes the run on relaunch; the Live Activity has Pause/Resume buttons (`Shared/RunActivityIntents.swift`, `LiveActivityIntent` + `RunControl`). The X (top left) closes before Start and asks "Discard this run?" during a run. Location off: a card with Open Settings replaces Start; Precise Location off: a note. Home shows "Get set up" tiles (Apple Health, Location) only while one is off.
- Apple Health (`Core/Services/HealthService.swift`) is the universal connection to other running apps (Strava, Garmin, Nike and the Watch all save runs to Health). Optional everywhere: an onboarding step after the name ("Connect Apple Health", skippable) and Profile > Connected apps. iOS never reveals read permissions, so reads are best-effort: age/height/weight Health returns fill those answers and their onboarding steps are skipped (`Answers.fromHealth`). Sync runs on launch, on foreground and via a background observer: running workouts since the plan start become runs (`source: apple_health`, id = the Health workout UUID, so it's idempotent); a run on a day with an open planned run checks it off, others go to the Log tab only. Never double counts: runs Kiki wrote (metadata `KikiRunID`) are skipped, as is any Health run overlapping a run already in Kiki (Kiki's recording wins); deleting an imported run ignores that time window for good. Kiki's GPS runs are written to Health with their route after saving.
- Build: `xcodebuild -project ios/kiki.xcodeproj -scheme kiki -destination 'platform=iOS Simulator,name=iPhone 17' build`.
- Default actor isolation is MainActor; Codable models are `nonisolated`.
- Data: `TrainingStore` = disk cache + optimistic updates + persistent outbox (runs and workout status). Client-generated UUIDs make writes idempotent.
- Routing (`RootView`): onboarding (persisted in UserDefaults) → welcome → `MainTabView` (the RevenueCat paywall is presented over it after onboarding) (Home / Plan / ▶︎ / Log / Profile) on the native glass tab bar. The ▶︎ is not a tab: an empty, disabled placeholder tab holds the middle slot and `RunTabButton` (a 44pt black circle with a Volt play triangle, the one Volt-on-button exception) is laid over it from outside the tab bar, positioned from the bar's frame (`TabBarFrameReader`). The bar never receives the touch, so its glass highlight doesn't slide to it (handling it in the selection, or a button inside the bar, is too late). It hides with the bar on pushed screens via `TabBarState` (set by `hidesTabBar`); minimize-on-scroll is off so it always has a bar under it; the selection binding still turns a drag onto the slot into opening the tracker. The tracker opens linked to today's run if one is still to do, else a free run. Tab icons are outlines (14pt regular, `MainTabView.tabIcon`), filled when selected; iOS 26 fixes the bar's height and label fonts.
- "Which days can you run?" (`RunDaysSelector`, also the Profile Run days editor) fits one screen and starts empty in onboarding: seven day tiles in a row, the hint, then a "Long run day" title (subtitle "Your longest run of the week.") over the picked days as the same tiles (same width, packed left), with Kiki's default (Saturday, else Sunday, else the last run day) preselected; no caption. The coach puts long runs on `profile.longRunDay`.
- Runners who aren't new are asked their weekly distance and longest recent run (`.weeklyVolume`, `.longestRun`), so the plan picks up where they are; new runners skip both.
- Onboarding answers are only AI inputs: the main app never branches on goal (goal wording lives in `Plan.displayName`). Question options and inputs live in `Features/Shared/Questions.swift` and `Design/Inputs.swift`, shared by onboarding and the Profile tab (`ProfileFieldEditor`). "Change goal" reuses `OnboardingFlow` with `OnboardingModel(mode: .newGoal, profile:)`. Every answer must stay editable from You.
- Onboarding ↔ Profile tab: every onboarding answer must stay editable from the Profile tab. Options live in `Features/Shared/Questions.swift` and inputs in `Design/Inputs.swift` (shared by both); goal edits reuse the onboarding steps via `OnboardingModel(mode: .editGoal(step))`. Keep the two in sync both ways: when you change an onboarding question, cross-check `YouView` (rows), `ProfileFieldEditor` (titles, name field) and `GoalDetailView` (goal rows); when you change an editor in the Profile tab, cross-check the matching onboarding step.
- `APIClient` never sends cookies (Better Auth rejects cookie requests without an Origin); auth is the bearer token only.
- API base URL comes from the `KIKI_API_BASE_URL` build setting: Debug = `http://localhost:3000`, Release = `https://kikirunning.com`.
- RevenueCat: Debug uses the Test Store key (simulated purchases), Release uses the `appl_` key. Custom paywall (`PaywallView`), Customer Center in the Profile tab.
- SDK identity: `Identity.identify` / `ensureIdentified` sets the same user ID in PostHog, RevenueCat (`logIn` + AppsFlyer/PostHog attribution) and AppsFlyer (`customerUserID`).
- AppsFlyer on-device events (`Attribution` in `Analytics.swift`): `af_complete_registration` (new users), `af_start_trial`, `af_subscribe`. They feed SKAN conversion values for Meta/TikTok; no revenue (RevenueCat sends revenue S2S). Campaigns optimize for StartTrial.
